# Security

Do not open public issues containing API keys, private knowledge bases or personal conversation logs. Use GitHub private security reporting if enabled. If it is unavailable, open only a non-sensitive request for a private contact route; do not disclose exploit details publicly. No security email or response SLA is currently defined.

Rotate exposed provider credentials through the provider, remove them from release artifacts and inspect Git history before publishing. Keep .env.local, private knowledge, generated indexes, models and raw evaluation traces outside version control.
